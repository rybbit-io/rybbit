Nginx is a powerful web server and reverse proxy that makes it easy to proxy Rybbit tracking through your own domain. This guide shows how to configure Nginx to forward tracking requests to Rybbit servers while caching static scripts for better performance.

<Callout type="warn">
**Two settings make or break a first-party proxy:**

1. Enable **First-Party Proxy** in your Rybbit **Site Settings → Privacy & Security**, so the visitor IP your proxy forwards in `X-Forwarded-For` is trusted directly.
2. Forward **all** of the browser's request headers, not a hand-picked few. Rybbit's bot detection expects the headers every real browser sends (`Accept`, `Accept-Language`, `Accept-Encoding`, `Sec-Fetch-*`) — proxies that forward only `User-Agent` get their events accepted with `200 OK` but classified as bot traffic. Use `X-Forwarded-For` for the visitor IP; `X-Real-IP` does not survive Rybbit Cloud's edge.
</Callout>

## Overview

Nginx's `proxy_pass` directive lets you forward requests from your domain to Rybbit's servers. Combined with caching, this provides excellent performance and reliability for proxying analytics.

**What you'll achieve:**
- Proxy all Rybbit endpoints through your domain
- Cache static scripts for better performance
- Forward necessary headers for accurate tracking
- Support all Rybbit features (session replay, Web Vitals, custom events)

## Prerequisites

- Nginx installed (version 1.18 or later recommended)
- SSL/TLS certificate configured (Let's Encrypt recommended)
- Your Rybbit instance URL:
  - **Cloud hosted**: `https://app.rybbit.io`
  - **Self-hosted**: Your instance URL
- Your Rybbit site ID (found in your dashboard)

## Implementation

<Steps>

### Configure Nginx Proxy

Add a new location block (or update existing configuration) in your Nginx site configuration:

<Tabs items={['Full Proxy (Recommended)', 'Minimal Proxy', 'With Cache Zone']}>
<Tab>

```nginx
# /etc/nginx/sites-available/yourdomain.com
server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    # Your SSL configuration
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # Your main site configuration
    location / {
        # Your regular site config...
    }

    # Rybbit Analytics Proxy
    # nginx passes the browser's other request headers through unchanged.

    # Main tracking script
    location = /analytics/script.js {
        proxy_pass https://app.rybbit.io/api/script.js;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # Session replay script (loaded only when session replay is on)
    location = /analytics/replay.js {
        proxy_pass https://app.rybbit.io/api/replay.js;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # Event tracking endpoint (not cached)
    location = /analytics/track {
        proxy_pass https://app.rybbit.io/api/track;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # User identification endpoint (not cached)
    location = /analytics/identify {
        proxy_pass https://app.rybbit.io/api/identify;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # Site configuration endpoint
    location /analytics/site/tracking-config/ {
        proxy_pass https://app.rybbit.io/api/site/tracking-config/;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # Feature flag evaluation (not cached)
    location ~ ^/analytics/site/[^/]+/feature-flags/evaluate$ {
        rewrite ^/analytics/(.*)$ /api/$1 break;
        proxy_pass https://app.rybbit.io;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }

    # Session replay recording endpoint (not cached)
    location /analytics/session-replay/record/ {
        proxy_pass https://app.rybbit.io/api/session-replay/record/;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;

        # Allow larger uploads for session replay
        client_max_body_size 10M;
    }
}
```

This covers every endpoint the tracking script calls. Web vitals are bundled into `script.js`; `replay.js` loads only when session replay is on. If the feature-flag route isn't proxied, `rybbit.flag()` silently returns your fallback.

<Callout type="info">
Replace `app.rybbit.io` with your self-hosted Rybbit instance URL if you're not using the cloud version.
</Callout>

<Callout type="warn">
Keep variables out of `proxy_pass`. With a variable such as `$1`, nginx resolves the upstream hostname per request and returns `502` unless you configure a `resolver`. And in a regex location (`location ~`), a `proxy_pass` with a fixed path such as `/api/track` fails `nginx -t`; only a path built from variables is allowed there, and that brings back the `resolver` requirement. That's why the paths with a site ID use prefix locations, or a `rewrite` followed by a `proxy_pass` without a path.
</Callout>

```nginx
server {
    listen 443 ssl http2;

    # SSL configuration
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;

    # Main tracking script
    location = /analytics/script.js {
        proxy_pass https://app.rybbit.io/api/script.js;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_ssl_server_name on;
    }

    # Event tracking
    location = /analytics/track {
        proxy_pass https://app.rybbit.io/api/track;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_ssl_server_name on;
    }
}
```

<Callout type="warn">
A minimal setup proxies only `script.js` and `/track`. The script then can't fetch your site's tracking config, so it ignores every setting on the site's **Tracking** tab and runs on built-in defaults: pageviews, SPA navigation, query strings and outbound links are tracked; web vitals, error tracking, session replay, button clicks, copy and form tracking stay off; feature flags return their fallback; and `identify()` and `setTraits()` can't reach `/identify`, so traits aren't stored and earlier anonymous activity isn't linked to the user. Use the full proxy unless that's what you want.
</Callout>

<Tab>

The other tabs don't cache anything: `proxy_cache_valid` has no effect without a `proxy_cache` zone. To cache the scripts at your proxy, define a cache zone:

```nginx
# /etc/nginx/nginx.conf (http block)
http {
    # Define cache zone for Rybbit
    proxy_cache_path /var/cache/nginx/rybbit
        levels=1:2
        keys_zone=rybbit_cache:10m
        max_size=100m
        inactive=60m
        use_temp_path=off;

    # ... rest of http config
}
```

Then add the cache directives to the script locations in your site config:

```nginx
# /etc/nginx/sites-available/yourdomain.com
server {
    # ... server config

    location = /analytics/script.js {
        proxy_pass https://app.rybbit.io/api/script.js;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_ssl_server_name on;

        # Use the cache zone
        proxy_cache rybbit_cache;
        proxy_cache_valid 200 1h;
        proxy_cache_key "$scheme$request_method$host$request_uri";
        add_header X-Cache-Status $upstream_cache_status;
    }

    # ... other locations
}
```

Do the same for `replay.js`. If you also cache `/analytics/site/tracking-config/`, keep it short (`proxy_cache_valid 200 5m;`) so changes you make in the dashboard reach visitors. Never cache the POST endpoints.

</Tab>

<Callout type="warn">
**Important**: The `proxy_set_header X-Real-IP` and `X-Forwarded-For` headers are critical for accurate geolocation and user identification. Without these, all traffic will appear to come from your Nginx server's IP.
</Callout>

### Update Your Tracking Script

Update your HTML to load the script from your proxied domain:

```html
<!DOCTYPE html>
<html>
<head>
    <!-- ... other head elements -->
    <script src="/analytics/script.js?siteId=YOUR_SITE_ID" defer></script>
</head>
<body>
    <!-- Your content -->
</body>
</html>
```

Replace `YOUR_SITE_ID` with your actual site ID from the Rybbit dashboard. Older snippets that pass the ID as `data-site-id` still work.

Keep the proxied file named `script.js`. The script cuts its own URL at `/script.js` to find where to send events, so a renamed file (for example `/analytics/a.js`) sends every request to the wrong place.

## How It Works

Nginx's `proxy_pass` directive transparently forwards requests to Rybbit's servers:

1. Browser requests `https://yourdomain.com/analytics/script.js`
2. Nginx matches the location block and forwards to `https://app.rybbit.io/api/script.js`
3. Nginx sets necessary headers (`X-Real-IP`, `X-Forwarded-For`) for accurate tracking
4. Response is cached (if configured) and sent back to browser
5. All subsequent tracking requests follow the same pattern

The Rybbit script auto-detects it's being served from your domain and sends all tracking data to your domain's `/analytics/*` endpoints.

## Performance Optimization

### Caching Strategy

Configure different cache durations based on content type (requires the cache zone from the **With Cache Zone** tab). These blocks replace the matching ones from the **Full Proxy** tab; don't add them alongside. nginx picks an exact-match `location =` over a regex one, and a repeated prefix location fails `nginx -t`.

```nginx
# Scripts - nginx follows Rybbit's Cache-Control: 1 hour for script.js, 1 day for replay.js
location ~ ^/analytics/(script|replay)\.js$ {
    rewrite ^/analytics/(.*)$ /api/$1 break;
    proxy_pass https://app.rybbit.io;
    # ... proxy headers
    proxy_cache rybbit_cache;
    proxy_cache_valid 200 1h;
    proxy_cache_valid 404 1m;  # Cache 404s briefly
}

# Config - cache for 5 minutes (changes when you update dashboard settings)
location /analytics/site/tracking-config/ {
    proxy_pass https://app.rybbit.io/api/site/tracking-config/;
    # ... proxy headers
    proxy_cache rybbit_cache;
    proxy_cache_valid 200 5m;
}

# Tracking - never cache (each request is unique)
location ~ ^/analytics/(track|identify)$ {
    rewrite ^/analytics/(.*)$ /api/$1 break;
    proxy_pass https://app.rybbit.io;
    # ... proxy headers
    # No caching directives
}
```

### Gzip Compression

Enable compression for JavaScript files:

```nginx
# In http or server block
gzip on;
gzip_vary on;
gzip_types application/javascript text/javascript;
gzip_min_length 1000;
```

### Connection Pooling

Keep connections to Rybbit backend alive for better performance:

```nginx
upstream rybbit_backend {
    server app.rybbit.io:443;
    keepalive 32;
}

location /analytics/ {
    proxy_pass https://rybbit_backend/api/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    # With an upstream block, Host and SNI default to "rybbit_backend"
    proxy_set_header Host app.rybbit.io;
    proxy_ssl_server_name on;
    proxy_ssl_name app.rybbit.io;
    # ... other proxy headers
}
```

### Proxy Buffering

For better performance with larger session replay uploads:

```nginx
location /analytics/session-replay/record/ {
    proxy_pass https://app.rybbit.io/api/session-replay/record/;
    # ... proxy headers

    proxy_buffering on;
    proxy_buffer_size 4k;
    proxy_buffers 8 4k;
    proxy_busy_buffers_size 8k;
    client_max_body_size 10M;
}
```

## Security Considerations

### Rate Limiting

Protect your proxy from abuse with rate limiting:

```nginx
# In http block
http {
    limit_req_zone $binary_remote_addr zone=analytics_limit:10m rate=10r/s;

    # ... rest of config
}

# In server block
location = /analytics/track {
    limit_req zone=analytics_limit burst=20 nodelay;
    proxy_pass https://app.rybbit.io/api/track;
    # ... proxy headers
}
```

This limits to 10 requests per second per IP, with bursts up to 20.

### Request Size Limits

Set appropriate limits for different endpoints:

```nginx
# Default for most endpoints
client_max_body_size 1M;

# Larger limit for session replay
location /analytics/session-replay/record/ {
    client_max_body_size 10M;
    # ... proxy config
}
```

### Security Headers

Add security headers to your responses:

```nginx
add_header X-Content-Type-Options nosniff;
add_header X-Frame-Options DENY;
add_header Referrer-Policy strict-origin-when-cross-origin;
```

## Troubleshooting

### 502 Bad Gateway

**Problem**: Nginx returns 502 error when accessing analytics endpoints.

**Solution**:
1. Check Rybbit backend is accessible:
   ```bash
   curl -I https://app.rybbit.io/api/script.js
   ```
2. Verify `proxy_ssl_server_name on` is set
3. If the error log says `no resolver defined to resolve app.rybbit.io`, a `proxy_pass` contains a variable (such as `$1`). Remove the variable (use a prefix location, or `rewrite ... break` with a `proxy_pass` that has no path), or add a `resolver` directive
4. Check Nginx error logs:
   ```bash
   sudo tail -f /var/log/nginx/error.log
   ```

### `nginx -t` fails on a regex location

**Problem**: `nginx -t` reports `"proxy_pass" cannot have URI part in location given by regular expression`.

**Solution**: A `location ~` block can't use a `proxy_pass` with a fixed path such as `/api/...` (a path built from variables is allowed, but then nginx needs a `resolver`). Use a prefix location (`location /analytics/session-replay/record/`), or keep the regex and rewrite the URI first:

```nginx
location ~ ^/analytics/site/[^/]+/feature-flags/evaluate$ {
    rewrite ^/analytics/(.*)$ /api/$1 break;
    proxy_pass https://app.rybbit.io;
    # ... proxy headers
}
```

### Cache not working

**Problem**: `X-Cache-Status` always shows `MISS`.

**Solution**:
1. Verify cache directory exists and is writable
2. Check `proxy_cache_path` is defined in http block
3. Ensure `proxy_cache` directive uses correct zone name
4. Check cache key is consistent:
   ```nginx
   proxy_cache_key "$scheme$request_method$host$request_uri";
   ```

### Incorrect geolocation in Rybbit

**Problem**: All visitors show same location (your server's location).

**Solution**:
Ensure you're forwarding client IP headers, and that **First-Party Proxy** is on in your site settings:
```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

### SSL errors in Nginx logs

**Problem**: Logs show SSL verification errors when connecting to Rybbit.

**Solution**:
Add `proxy_ssl_server_name on` to enable SNI:
```nginx
location /analytics/ {
    proxy_pass https://app.rybbit.io/api/;
    proxy_ssl_server_name on;  # Enable SNI
    # ... other config
}
```

## Advanced Configuration

### Subdomain Proxy

Use a dedicated subdomain for analytics:

```nginx
# /etc/nginx/sites-available/analytics.yourdomain.com
server {
    listen 443 ssl http2;
    server_name analytics.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/analytics.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/analytics.yourdomain.com/privkey.pem;

    # Proxy all requests to Rybbit
    location / {
        proxy_pass https://app.rybbit.io/api/;
        proxy_set_header Host app.rybbit.io;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_ssl_server_name on;
    }
}
```

Then use:
```html
<script src="https://analytics.yourdomain.com/script.js?siteId=123" defer></script>
```

### Multiple Rybbit Instances

If you need to proxy multiple Rybbit instances:

```nginx
location /analytics-prod/ {
    proxy_pass https://prod.rybbit.io/api/;
    # ... proxy config
}

location /analytics-staging/ {
    proxy_pass https://staging.rybbit.io/api/;
    # ... proxy config
}
```
