```
GET /api/sites/:site/retention
```

Returns cohort-based retention analysis data. Users are grouped into cohorts based on their first visit, and retention is tracked over subsequent time periods.

A user joins a cohort only when the requested time range holds their first visit: anyone seen in the 90 days before the range starts is a returning visitor and is left out. Returns are counted up to the end of the range. Filters select users by their first visit; any later activity counts as a return.

### Path Parameters

<TypeTable
  type={{
    site: {
      description: 'Site ID or site identifier',
      type: 'string | number',
      required: true,
    },
  }}
/>

### Query Parameters

Accepts all [Common Parameters](/docs/api/getting-started#common-parameters) plus the following:

<TypeTable
  type={{
    mode: {
      description: 'Retention period granularity. Weeks start on Monday, in the requested time zone',
      type: 'string',
      typeDescription: '"day" | "week"',
      default: 'week',
    },
    range: {
      description: 'Number of trailing days to analyze (7-365). Only used when no time range is sent',
      type: 'number',
      default: 90,
    },
  }}
/>

A range longer than 53 weeks (weekly) or 92 days (daily) is cut to its most recent periods, and `truncated` is `true` in the response.

### Understanding Retention Data

The retention data shows how many users from each cohort return in subsequent periods:

- **Period 0**: Always 100% (the cohort's first visit)
- **Period 1**: Users who returned 1 week later
- **Period 2**: Users who returned 2 weeks later
- etc.

A `null` value indicates that the period falls after the end of the range for that cohort. A value of `0` means the period has been observed and nobody came back.
