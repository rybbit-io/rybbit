```
GET /api/site-transfers/:transferId
```

The recipient's view of a [site transfer](/docs/api/sites/create-transfer): which site is being offered and by whom. Only the person the transfer was sent to can read it.

**Authentication:** a signed-in dashboard session belonging to the recipient. API keys don't work here: the route names no site or organization to check a key against, so every API key (personal, scoped or organization) gets `401`. The examples send the session cookie. The JavaScript example is for Node.js: browsers don't let scripts set a `Cookie` header.

### Path Parameters

<TypeTable
  type={{
    transferId: {
      description: "Transfer ID, the last segment of the emailed transfer link",
      type: "string",
      required: true,
    },
  }}
/>

### Response

<TypeTable
  type={{
    id: {
      description: "Transfer ID",
      type: "string",
    },
    site: {
      description: "The site being transferred",
      type: "{ siteId: number, name: string, domain: string }",
    },
    sourceOrganizationId: {
      description: "Organization the site is in now",
      type: "string",
    },
    sourceOrganizationName: {
      description: "Name of that organization",
      type: "string",
    },
    sentBy: {
      description: "Email of the person who sent the transfer, if known",
      type: "string | null",
    },
    expiresAt: {
      description: "When the link stops working",
      type: "string",
      typeDescription: "ISO 8601 UTC",
    },
  }}
/>

### Error Responses

Errors use the standard body `{ error, code, message, resolution }`.
