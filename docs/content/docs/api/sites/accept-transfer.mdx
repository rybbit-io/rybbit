```
POST /api/site-transfers/:transferId/accept
```

Accepts a [site transfer](/docs/api/sites/create-transfer) and moves the site, with its data, into the organization you choose. The move has the same effects as [Move Site](/docs/api/sites/move), and the site's private link is also removed.

**Authentication:** a signed-in dashboard session belonging to the recipient. API keys don't work here: the route names no site or organization to check a key against, so every API key (personal, scoped or organization) gets `401`. The examples send the session cookie. You must be an `admin` or `owner` of the target organization, and the person who sent the transfer must still be able to transfer the site.

### Path Parameters

<TypeTable
  type={{
    transferId: {
      description: "Transfer ID, the last segment of the emailed transfer link",
      type: "string",
      required: true,
    },
  }}
/>

### Request Body

<TypeTable
  type={{
    organizationId: {
      description: "ID of your organization to move the site into",
      type: "string",
      required: true,
    },
  }}
/>

### Response

<TypeTable
  type={{
    success: {
      description: "Whether the site was moved",
      type: "boolean",
    },
    siteId: {
      description: "The transferred site",
      type: "number",
    },
    organizationId: {
      description: "The site's new organization",
      type: "string",
    },
  }}
/>

### Error Responses

Errors use the standard body `{ error, code, message, resolution }`.

<TypeTable
  type={{
    "400": {
      description: "organizationId missing, or the site is already in that organization",
      type: "object",
    },
    "401": {
      description: "No signed-in session (including any request authenticated only with an API key)",
      type: "object",
    },
    "403": {
      description: "Signed in with a different email address (reason \"wrong_account\", with a masked recipientEmailHint), or the address isn't verified on Rybbit Cloud (reason \"email_unverified\")",
      type: "object",
    },
    "404": {
      description: "The transfer doesn't exist, was cancelled, or has expired",
      type: "object",
    },
    "409": {
      description: "The site has moved since the transfer was sent",
      type: "object",
    },
  }}
/>

A `403` is also returned when you aren't an admin or owner of the target organization, the target organization is at its plan's site limit, or the sender can no longer transfer the site (the transfer is then cancelled).
