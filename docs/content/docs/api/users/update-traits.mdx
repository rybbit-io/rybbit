```
PUT /api/sites/:site/users/:userId/traits
```

Replaces the user's stored traits with the object you send. Unlike `identify()`, which merges, this overwrites: traits you leave out are removed. Keys with a null value are dropped. The profile is created if the user doesn't have one yet.

**Permissions:** the `member` role or above on the site. API keys need the `users:write` scope.

### Path Parameters

<TypeTable
  type={{
    site: {
      description: "Site ID or site identifier",
      type: "string | number",
      required: true,
    },
    userId: {
      description: "Identified user ID (the ID passed to identify())",
      type: "string",
      required: true,
    },
  }}
/>

### Request Body

<TypeTable
  type={{
    traits: {
      description: "The complete set of traits to store",
      type: "object",
      typeDescription: "Max 2 KB as JSON",
      required: true,
    },
  }}
/>

### Response

<TypeTable
  type={{
    success: {
      description: "Whether the traits were saved",
      type: "boolean",
    },
  }}
/>

### Error Responses

Errors use the standard body `{ error, code, message, resolution }`.

<TypeTable
  type={{
    "400": {
      description: "Invalid payload (traits missing, not an object, or over 2 KB)",
      type: "object",
    },
    "403": {
      description: "Missing role on the site or the users:write scope",
      type: "object",
    },
    "500": {
      description: "Failed to update user traits",
      type: "object",
    },
  }}
/>
