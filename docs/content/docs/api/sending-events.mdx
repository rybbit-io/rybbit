```
POST /api/track
```

Send events from servers, mobile apps, or any platform that can make an HTTP request. The body is JSON, and every event needs a `site_id` and a `type`.

Send an API key as `Authorization: Bearer your_api_key_here` when you report events on a visitor's behalf. A key only counts here if it has access to the site and is full-access or holds the `ingest:write` permission. With such a key, Rybbit uses the `ip_address` and `user_agent` you send for the visitor ID, geolocation and device detection, and skips every bot check except user-agent classification. Without one (including a key sent as `?api_key=`), `ip_address` and `user_agent` are ignored and the event is treated as a browser hit from your server. They are still validated, so a malformed value returns `400`. There is no domain validation.

<Callout type="warn">
Bot detection still runs. Without a qualifying key, a request from a server HTTP client (curl, python-requests, node-fetch, Go's HTTP client and similar) is classified as a bot. With one, the reported user agent is still classified, so pass the visitor's real user agent. With bot blocking on (the default), bot events are stored as bot traffic and never appear in your analytics, but the response is still `200` with `{"success":true}`.
</Callout>

To keep visitors apart, send an `anonymous_id` per visitor, or the visitor's `ip_address` and `user_agent` with a qualifying key. Otherwise every event shares your server's IP and user agent and counts as one visitor.

### Response

| Status | Body | Meaning |
|--------|------|---------|
| `200` | `{"success":true}` | Accepted. Events classified as bots get the same response. |
| `200` | `{"success":true,"message":"Event not tracked - ... excluded"}` | Matched one of the site's exclusions and was not stored. |
| `200` | Plain text, e.g. `Site over monthly limit, event not tracked` or `Site has no plan, event not tracked` | Not stored. The body is not JSON, so read it as text. |
| `400` | `{"success":false,"error":"Invalid payload","details":...}` | Validation failed; `details` lists the failing fields. |
| `404` | `{"success":false,"error":"Site not found"}` | Unknown `site_id`. |

### Rate Limiting

`/api/track` itself isn't rate limited, but on Rybbit Cloud every request that carries a Bearer key counts against the key owner's API limits: a burst of 50 requests per 10 seconds, plus 5,000 (Standard) or 25,000 (Pro) requests per day. See [Rate Limits](/docs/api/getting-started#rate-limits-cloud-only).

When a limit is reached, `/api/track` doesn't return `429`. The key simply stops counting: the event is still ingested, but as untrusted traffic, so `ip_address` and `user_agent` are ignored and bot detection runs in full. Self-hosted instances have no API rate limits.

### Identifying Users

```
POST /api/identify
```

Links a visitor to your user ID and stores traits on the user's profile. This is the endpoint `rybbit.identify()` and `rybbit.setTraits()` call in the browser. Send the same `Authorization: Bearer` key as for `/api/track` if you pass `ip_address` or `user_agent`; without a qualifying key they're ignored.

      required: true,

    anonymous_id: {
      description: 'The anonymous_id you send with this visitor\'s events. When omitted, the visitor is derived from IP and user agent.',

      typeDescription: '1-255 chars',
    },
    ip_address: {
      description: "Visitor's IP. Used only with a qualifying Bearer key.",
      type: 'string',
      typeDescription: 'Valid IPv4 or IPv6 address',
    },
    user_agent: {
      description: "Visitor's user agent. Used only with a qualifying Bearer key.",
      type: 'string',

    traits: {
